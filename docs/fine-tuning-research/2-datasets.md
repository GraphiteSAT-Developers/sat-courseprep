# 2. Public datasets, benchmarks and open models for math-tutoring dialogue

_Research note, 2026-10-16. Scope: what we can use for (a) evaluation, (b) extra training data, (c) format reference for the Qwen3 LoRA SFT + DPO tutor in `docs/fine-tuning-plan.md`. This is not legal advice. Every "commercial OK?" verdict needs counsel's sign-off before any third-party data enters a training run for a paid product used by minors._

**How this was checked.** From this sandbox, huggingface.co and arxiv.org could not be reached (proxy 403 / DNS). GitHub READMEs were fetched directly. Facts from a Hugging Face card or an arXiv page come from search-engine snippets and are marked **(HF/arXiv via search)**. Anything I could not confirm at all is marked **UNVERIFIED**. Before use, open the LICENSE file in the exact repo or revision you download. Several projects show **conflicting licenses** between their GitHub README and their HF card (noted below).

## 2. Recommendations

**Bottom line: train only on our own Sonnet-generated dialogues. Use public resources for evaluation, judge calibration and design reference.** Nothing public is at SAT level with a Desmos/Bluebook workflow, so mixing in public data would teach the wrong register and add license and privacy risk for little gain.

### Use

1. **MathTutorBench: the automatic regression eval.** Run it on the base Qwen3, on each SFT/DPO checkpoint and on the Sonnet baseline. It answers "did our SFT damage general pedagogy or math expertise?" (the paper finds a trade-off between solving and tutoring). It does **not** replace our own held-out gate: it uses its own prompts, GSM8K-level math and no item block. Treat a drop of a few points as a warning, not a blocker.
2. **MRBench (V1–V3) and the BEA 2025 data: judge calibration plus a cross-check of our rubric.** Its 8 human-annotated dimensions map to our rubric (revealing answer ↔ leak; mistake identification/location ↔ "mistake identified, location named"; tutor tone; actionability ↔ hint discipline). Before trusting the Opus judge on our dialogues, run it on MRBench responses and measure agreement with the human labels per dimension. This is a free first pass of the plan's "judge-human agreement ≥ 0.75" step and catches rubric wording problems before the owner labels 100 pairs. CC BY-SA is fine for internal eval; do not redistribute modified copies except under SA.
3. **Pedagogical reward model (MathTutorBench): a second-family scorer.** Use it as a cheap tiebreaker or as an extra DPO pair filter (keep a pair only if both the Opus judge and the RM agree on the order). Do not optimise against it directly; the authors warn about reward hacking.
4. **TutorRL / PedagogicalRL: the design for Phase B.** Their reward ("did the simulated student solve it afterwards" minus a leak penalty from a judge) is very close to what we can build: our deterministic leak check plus the deterministic grader on the simulated student's final attempt. That is a ready RFT reward on Fireworks/Bedrock, and a stronger signal than judge-only DPO pairs. TutorRL-7B is also a useful open baseline on our held-out eval (Qwen2.5-7B base, CC-BY-4.0 per repo; verify the model card).
5. **Reference only (no copying):** MathDial's teacher-move labels and Bridge's error-type/strategy labels, to check that our personas and hint levels cover the moves human tutors use; SocraTeach's six student types; the Eedi misconception taxonomy (concepts only); the LearnLM rubric dimensions. Concepts are not copyrightable; text is, so write our own.

### Avoid, and why

- **CoMTA**: Khan's license forbids training and allows only internal noncommercial testing.
- **SocraTeach / SocraticLM weights, Eedi QATD-2k, Eedi Kaggle data**: NC licenses (or likely NC competition rules). We are a paid product.
- **Bridge, NCTE, Eedi QATD as training data**: real minors' conversations. Even when anonymized, putting real children's dialogue into the weights of a product for minors is a privacy and reputational risk we do not need. Our plan's data story ("all synthetic, all original items") is clean; keep it.
- **TutorChat, MathChatSync, SocraticMATH, and MathDial's student turns**: generated by OpenAI models. OpenAI's terms restrict using outputs to build competing models. Licenses are unclear and the level is wrong anyway.
- **AGIEval SAT-Math and any "SAT question" dumps on HF**: College Board content; violates `docs/item-writing.md` and our data rules.
- **MathDial as training data**: CC BY-SA vs CC BY conflict, and share-alike on weights is unsettled. It is low value anyway (grade-school, no calculator). Eval only, unless counsel clears it.
- **Qwen2.5-Math-* as the base**: solver-tuned, weak at dialogue. Our tutor does not solve.

## 3. Running the benchmarks against an OpenAI-compatible endpoint

Assume the candidate is served at `$BASE` (Together/Fireworks: their `/v1`; self-hosted: `vllm serve <hf-or-local-path> --enable-lora --lora-modules sat-tutor=<adapter> --seed 42`, then `BASE=http://localhost:8000/v1`, `MODEL=sat-tutor`).

### 3.1 MathTutorBench (commands from the repo README)

```bash
git clone https://github.com/eth-lre/mathtutorbench && cd mathtutorbench
pip install -r requirements.txt            # check the README for the exact install step
# Expertise / student-understanding tasks (single prompt):
python main.py --tasks problem_solving.yaml --provider completion_api \
  --model_args base_url=$BASE,api_key=$KEY,model=$MODEL,is_thinking=True --output results/ --debug
# Dialogue (pedagogy) tasks need is_chat=True:
for t in mistake_correction scaffolding_generation pedagogy_following \
         scaffolding_generation_hard pedagogy_following_hard; do
  python main.py --tasks $t.yaml --provider completion_api \
    --model_args base_url=$BASE,api_key=$KEY,model=$MODEL,is_chat=True,is_thinking=True --output results/
done
# Score the pedagogy tasks with the reward model (local GPU, ~1.5B):
python reward_model/compute_scaffolding_score.py --data_path results/generations-$MODEL.json
python visualize.py --results_dir results/
```

Notes: `is_thinking=True` **disables** Qwen3 thinking (what we serve); `enable_thinking=True` is the alternative. Defaults: temperature 0, max_tokens 2048. Run `--debug` first: the README warns full runs on a paid API cost about $35–200. The benchmark sends its own system prompt, so our LoRA is tested off-distribution. Report it as "general pedagogy retained", next to the base model's score. To run the Sonnet baseline, it needs an OpenAI-compatible route (for example OpenRouter, as in the README; or Anthropic's OpenAI-compatible endpoint, UNVERIFIED whether the harness's parameters pass through cleanly).

### 3.2 MRBench / BEA 2025: two uses, a small harness of our own (no official runner for generation)

1. **Judge calibration (no tutor model needed).** For each MRBench record, feed `conversation_history` plus each annotated response to our judge prompt, mapped to the 8 dimensions. Compare with the human labels (accuracy and macro-F1 per dimension, as the BEA 2025 shared task scored them; see the [findings](https://aclanthology.org/2025.bea-1.77)). Target ≥ 0.75 agreement on "revealing answer" and "mistake identification" before trusting the judge's leak and mistake scores.
2. **Next-turn generation.** For each `conversation_history`, call `POST $BASE/chat/completions` with a system prompt that adapts our rules (no item block, no Desmos), generate one tutor turn, and have the calibrated judge label it on the 8 dimensions. Compare the candidate, the base Qwen3 and Sonnet. Script sketch: about 60 lines in `web/scripts/` reusing the judge client. Keep MRBench files out of the repo (SA) or keep them unmodified with attribution.

### 3.3 PedagogicalRL eval harness (optional)

The repo evaluates tutors in simulated multi-turn sessions (frozen student plus leak/helpfulness judges) through OpenRouter/Gemini adapters in `src/inference_providers/`. A generic OpenAI-compatible base URL is **UNVERIFIED**; OpenRouter-style clients usually accept a `base_url` override. Use this only to reproduce their leak-vs-solve Pareto plot for our model. Our own held-out gate already measures the same thing on SAT items.

### 3.4 Our own gate stays primary

The plan's held-out pairwise eval (section 5) is the only eval that tests our prompt, our item block, Desmos reproducibility and Bluebook formatting. The public benchmarks above are supporting evidence: (i) no regression on general pedagogy (MathTutorBench), (ii) a calibrated judge (MRBench), (iii) a literature baseline (TutorRL-7B, SocraticLM internally only).
